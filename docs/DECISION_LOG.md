# DECISION LOG — CoilClash (Snake Arena)

> Mirror of §46 in `MASTER_PROMPT_SNAKE_ARENA.md`. That file is the source of
> truth; keep both in sync when appending.

| # | Decision | Rationale | Reversible? |
|---|---|---|---|
| 1 | Boost costs power, no cooldown | Creates a real economic tradeoff and feeds the arena with motes | Yes — `boost_mode` enum |
| 2 | Circular arena with soft, non-lethal walls | Corner camping and unfair wall deaths both kill retention | Yes |
| 3 | Distance-sampled history ring buffer for bodies | Best smoothness-to-cost ratio; trivially supports growth | Hard |
| 4 | Custom spatial hash instead of physics bodies | 400+ Area3Ds is not viable on web/mobile | Hard |
| 5 | Self-collision off by default | Feels arbitrary in continuous movement | Yes |
| 6 | Rim-light threat colouring | Highest-impact readability feature | Yes |
| 7 | No ads in the first session run | First-session retention > first-session revenue | Yes (config) |
| 8 | Ad layer fully abstracted behind `AdProvider` | Lets us ship on web and mobile from one codebase and test without an SDK | Hard |
| 9 | 10% power buffer on eat rule | Removes coin-flip outcomes | Yes |
| 10 | Engine version pinned to **Godot 4.7.2 stable** | Repo's `project.godot` already declared features `"4.7", "GL Compatibility"`; newest stable 4.x available at Phase 0. Recorded in `docs/ENVIRONMENT.md`. | Yes |
| 11 | Dev sandbox has no GPU/audio/display; all AI-side runs are headless or under Xvfb+Mesa llvmpipe | Sandbox constraint, not a choice. Perf budgets (§19), audio quality, and touch feel must be human-verified on real hardware (Part C of `docs/HUMAN_TASKS.md`). `tools/setup_env.sh` restores the toolchain after sandbox restarts. | Yes |
| 12 | Repo's `3d/physics_engine="Jolt Physics"` removed → default GodotPhysics3D | Jolt is a GDExtension; §19 mandates Extensions Support = off for the web export, which would leave the primary target without a physics server. Gameplay barely uses physics (§6.4: one Area3D per head; bodies are MultiMesh + custom spatial hash). | Yes |
| 13 | Hand-rolled headless test runner (`tests/run_tests.gd`) instead of GUT | §9A explicitly allows it; zero external addons, deterministic exit codes, works fully headless in the sandbox. | Yes |
| 14 | Phase 1 boot flow: `main.tscn` → arena directly, no menu (menu screens don't exist until Phase 8) | Matches the §13.4 FTUE philosophy (straight into gameplay). Temporary dev flow; the MENU state path activates in Phase 8. | Yes |
| 15 | `.tscn` Transform3D values are serialized row-flat: `(X.x, Y.x, Z.x, X.y, Y.y, Z.y, X.z, Y.z, Z.z)`. NEVER hand-compute scene transforms — take the tuple from the engine (PackedScene.pack, or set rotation/look_at at runtime). | A hand-written transform with vector-grouped triples loads TRANSPOSED — the arena sun pointed up and the ground rendered unlit (caught by the screenshot harness, fixed by re-serializing from the engine). | No (format rule) |
| 16 | Snake body = one `MultiMeshInstance3D` per snake with **fixed-cap buffers**: `instance_count` set once to `max_segment_count` (§19 zero-alloc pattern); grow/shrink drive `visible_instance_count` only. | Per-grow buffer resizing errors every tick (buffers must match `instance_count` exactly) and reallocates; fixed cap is the §19-approved steady-state path. | Hard |
| 17 | MultiMesh **TRANSFORM_3D buffer is 16 floats per instance** in Godot 4.7 (`basis.x + w`, `basis.y + w`, `basis.z + w`, `origin + w`) — verified empirically: a 12-float buffer is REJECTED with "different size from existing buffer". | Docs implied 12 for TRANSFORM_3D; the engine validates 16. Empiricism wins. | No (engine behaviour) |
| 18 | Camera yaw convention bridge: snake `facing_angle_deg` (0° = +Z, positive → +X) vs camera yaw (0° = −Z, positive → −X) differ by 180°, so `camera_yaw = facing + 180°` and the rig position offset is `+facing` horizontal × distance. | First version tracked exactly backwards — head projected off-screen (caught by the new on-screen framing assertion in the verify harness, §50-compliant "see it before claiming it"). | No (convention rule) |
| 19 | Boost drain **also shrinks the body** (via `_sync_segment_target`) — a long snake boosts fast, so boosting must cost length as well as power. | Completes the §3.4 risk loop. Corpse-mote emission when shrinking is deferred to Phase 3 (mote system). | Yes |
| 20 | Phase 2 verify harness (`scenes/boot/verify.tscn`): replicates the boot state sequence (GameManager → PLAYING), pre-feeds `add_power(10)` before asserting boost (spawn power 2.0 < `min_boost_power` 4.0, so a fresh snake legitimately cannot boost — a "false fail" trap), asserts the §3.2 segment formula, checks the head projects on-screen, guards double-print with a `_finished` flag. | Exit criteria §50: every claim must be observed. The harness encodes them as executable checks with `CC_VERIFY_PASS`/`CC_VERIFY_FAIL` + exit codes. | Yes |
| 21 | §3.1 curves apply at **power 1 too** — tests assert the formula value (speed ≈ 10.68, turn ≈ 260.62) rather than the raw base constants (11.0 / 280.0). | The curve terms are non-zero at power 1; treating base constants as "power 1 values" is a misreading of §3.1. | No (spec reading) |
| 22 | Head visual = plain `MeshInstance3D` sphere (1.15× head radius, power-tier tinted), child-added by `SnakeBody`; the controller node itself has no mesh. | Keeps the controller physics-only while the body owns all visuals; a separate head instance avoids MultiMesh index-0 special-casing. | Yes |
| 23 | `add_power` growth eases in per segment (~0.25 s, `ease_out_cubic`); synchronous tests assert `_segments_target` (the target), not the live eased count. | §3.2 growth is an animation, not an instant resize; asserting the eased count would be timing-fragile. | Yes |
| 24 | MultiMesh buffers are **uploaded once per tick** (`_upload_buffers()` after the segment loop), not per segment write. | Per-write uploads re-sent the full 240-instance buffer 60×/tick at 60 segments; single upload keeps the §19 zero-churn goal. Growth is also deliberately +1 segment/tick, so the 60-segment phase check waits 90 ticks. | Yes |
| 25 | Economy managers (`CollectibleManager`, `SpawnManager`, `ScoreManager`) are **scene-level nodes created by arena.gd**, NOT autoloads. | §11 says "autoload or scene-level — decide, log it." They own run-scoped state that must die with the arena (restart = clean economy); autoloads are reserved for app-lifetime services (§22). | Yes |
| 26 | Initial population fills to 420 **instantly** at PLAYING; the 18/s cap applies to refill respawns only. | §11's "topped up organically rather than popping" describes refill after losses — an empty arena at run start would make the first seconds dead. | Yes |
| 27 | Boost-shed corpse motes carry **power only** (drain/4 = 0.55 each), score 0. | They are a refund of your own drained power, not free score; death-dropped motes (Phase 6) will carry score per §12.3. | Yes |
| 28 | Placeholder collectible visuals use engine primitives (prism ≈ octahedron, low-poly sphere ≈ dodecahedron); collect SFX are procedurally synthesized by `tools/gen_sfx.gd` (sine synthesis → `.wav`, committed). | §15 mandates procedural SFX over downloads; Phase 10 replaces/refines both. Recorded in `assets/CREDITS.md`. | Yes |
| 29 | The 420-population target counts **non-mote** collectibles only (motes are additive drops); the refill accumulator is capped at 1.0 spawn/tick. | Motes are transient drops, not population; an uncapped accumulator would pop-in a burst of respawns after a long full-arena stretch. | Yes |
| 30 | `ScoreManager` has an **injectable clock** (`clock_ms: Callable`, default `Time.get_ticks_msec`). | Combo timing (1.4 s window) is untestable against wall-clock time; the boxed-lambda clock makes the §12.3 table deterministic. (GDScript lambdas capture locals by value — the test clock reads through an Array.) | Yes |
| 31 | Arena shrink (§3.6) deferred to Phase 6; Surge implemented in Phase 3 (spawning system) with a light-beam announce — the HUD ping arrives with the Phase 8 HUD. | Shrink needs boundary-visual scaling + the "ARENA COLLAPSING" announce; surge is a spawn concern. | Yes |
| 32 | Boost motes drop at `radius * 1.4 + boost_mote_drop_distance` behind the head — must land OUTSIDE the collect radius. | Live verify caught it: at power ~200 the collect radius ≈ radius×1.4 exactly, so motes were re-collected instantly ~50% of the time (jitter) and boosting became free — the §3.4 risk loop broke. | No (exploit guard) |
| 33 | Ad completion is signal-based: `show_*` start an async show, emit `AdProvider.show_completed(result)` on EVERY path, and also return the final `AdResult` (coroutine). AdManager listens (ONE_SHOT) and races against its watchdog. | A provider that never resolves (crash/hang) must never freeze the game — `await provider.show()` would hang forever on a broken provider; a signal + watchdog race cannot. | No (safety) |
| 34 | GameManager transitions extended: `MENU → PAUSED_FOR_AD` and `GAME_OVER → PAUSED_FOR_AD` (and back) are valid. | §45.6 says the game "returns to the previous state" — and the highest-value placements fire at game-over (revive) and menu (menu-return interstitial). | Yes |
| 35 | The debug ad panel's controls are built in code (`_build_ui`) under a minimal hand-written `.tscn` shell. | Hand-authoring ~15 controls' property blocks in .tscn is error-prone (decision #15 lesson); the scene still exists per §13.1. | Yes |
| 36 | Dev builds with the mock provider auto-resolve consent to GRANTED (`ConsentManager.resolve()`) when state is UNKNOWN. | No UMP/consent UI exists until Phase 11 (§45.8); real providers will require explicit consent. Null/mobile paths stay strict. | Yes |
| 37 | Provider selection supports a `CC_AD_PROVIDER=null|mock` env override (sandbox testing only). | Lets the harness verify the §45.1 requirement "fully playable with AdProviderNull" without editing .tres files per run. | Yes |
| 38 | The `--script` test runner must NOT reference autoload identifiers at parse time AND must NOT `preload()` gameplay scripts (that force-compiles them in the same broken context — the autoload itself then fails). Runner reaches autoloads via the tree and enums via runtime `load()`. | Empirical: a parse-time preload of game_manager.gd produced "Identifier not found: EventBus" and poisoned the whole suite. | No (tooling) |
| 39 | AI body probe uses a RAW trail walk (`PositionHistory.trail_samples`, no cursors) + head-distance prefilter + recent-300-sample window (stride 3), refreshed at 5 Hz with cached reuse between decisions. | Cursor-based `read_at_arc` sampling measured ~0.9 ms per decision (§8.5 budget blown); raw reads + window ≈ 0.2 ms. 5 Hz staleness is below the §8.4 reaction_delay the AI already perceives through. | Yes |
| 40 | §8.5 budget scheduler: `AIDirector.can_afford_decide()` defers a decision when the frame's accumulated AI cost would exceed 60% of `ai_frame_budget_ms`. | Random stagger alone can cluster — measured a 3.78 ms spike when all 8 AI decided on one frame. The scheduler bounds worst-case frames regardless of phase luck. | Yes |
| 41 | `clusters_near` returns the TOP-5 collectibles by value; `get_motes_near` the top-3 motes. No full O(n²) census merging. | The full merge measured ~160 µs/call and ~130 µs/call respectively; top-k is behaviourally equivalent for steering (the AI heads for the best pickup, not a census). | Yes |
| 42 | GDScript rule: only insert into a typed Array when the element type ACTUALLY matches — inserting `[value, entry]` pairs into an `Array[Dictionary]` triggers a runtime type-conversion error per insert (~50 µs each; 2 ms/call measured before profiling found it). | Profiling caught the errors, not the logic — the insert "worked" (values coerced or dropped) while burning budget. | No (perf rule) |
| 43 | AI competence metric = path length, not displacement (a high-turn-rate snake legitimately coils; displacement ≈ 0 while path ≈ full speed). | The Phase 2 player check hit the same trap; the Phase 5 AI check now accumulates head movement per frame. | Yes |
| 44 | Combat broadphase = per-pair recent-trail walk with head-distance prefilter, NOT per-tick body-segment insertion into the SpatialHash. | §6.4 mandates a custom broadphase (no physics bodies) — the trail walk is the same semantics at a fraction of the rebuild cost (9 snakes × 240 segments × 60 Hz would dominate the §19 budget). Bodies are dense trails; only near-head windows can collide. | Yes |
| 45 | Eat-rule + rim-light comparisons use scaled-integer math (×10 vs ×11), not floating-point 1.10×. | Float wobble at exactly 1.10× (110.0 vs 100×1.10 = 110.000…01) flips the §9 matrix at its boundary — the table test caught it. Threat wins ties in rim classification. | No (correctness) |
| 46 | Hit-stop and the ad watchdogs run on REAL time (Time.get_ticks_msec / ignore_time_scale timers). | Engine.time_scale dilation made a 1.0 s watchdog take 6.6 s real — the exact §45.6 "stuck behind an ad" failure the watchdog exists to prevent. | No (safety) |
| 47 | The verify harness makes the player attackable-but-unkillable (god-mode meta) during scenarios A–E, clearing it only for the death scenario. | Combat is live from Phase 6; an AI kill mid-harness suspended input and broke later phases (boost checks). Invulnerability is victim-only — the player still kills normally. | Yes |
